How Configuration and Deployment Changes Trigger Large Cloud and SaaS Outages: An Empirical Study of 70 Public Postmortems

Pujitha Sri Lakshmi Paladugu
Independent Researcher · ORCID 0009-0001-5678-4022

Preprint · 2026-10-11 · 27 pages · Full text (PDF)

Abstract

Context. Cloud and software-as-a-service providers publish postmortems after large outages, and many name a change as the trigger, but this evidence has rarely been coded systematically. Objective. We characterise how changes trigger large outages: which change artifacts dominate, how rollout scope and missing safeguards relate to duration and blast radius, how such outages are detected and mitigated, and which validation gaps recur. Method. We coded 70 incidents from 22 providers (2019–2026) using only official vendor postmortems, analysed them with nonparametric tests and effect sizes, and synthesised the stated validation gaps into a ten-theme taxonomy using a reproducible keyword mapping with recorded overrides. A seeded rule-based re-coding of 20 incidents checked the consistency of the trigger codes. Results. Changes started 52 of 70 incidents (74.3%; 95% confidence interval 63.0–83.1%). Configuration changes alone accounted for 28 (53.8% of change-triggered incidents), ahead of infrastructure changes (16) and code deployments (8). Changes pushed globally at once produced wide impact in 10 of 11 cases. Changes applied to a single cluster or site still caused impact beyond that site in 10 of 11 cases. Only 19 of 52 change-triggered incidents were resolved by rollback. The most frequent gaps were testing that did not represent production conditions, missing or bypassed staged rollout, and missing semantic validation of configuration and data. Rule-based re-coding agreed with the original codes at κ = 0.87. Conclusions. Configuration and data need the same progressive, validated delivery as code. We derive an eleven-control Safe Change Checklist traced to the motivating incidents.

Keywords: configuration changes; incident postmortems; cloud outages; safe deployment; continuous deployment; site reliability engineering
